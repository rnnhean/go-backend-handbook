# 综合大作业：mini-coin 从 0 到上线

> 全部基于虚构项目，不涉及任何真实业务、真实接口或真实数据。

## 目标

独立完成一个"充值 + 查询余额"的服务，并把它部署到本地 Kubernetes（或 docker compose），具备测试、监控、限流、文档。

## 里程碑

### M1 基础服务（第 1~4 章）

- [ ] `GET /healthz` 返回 200
- [ ] `POST /v1/recharges` 支持幂等（`req_id` 唯一）
- [ ] `GET /v1/accounts/{uid}/balance`
- [ ] MySQL 建表 + 迁移脚本
- [ ] 单元测试覆盖 service 层

验收：`go test ./...` 通过；重复 `req_id` 不重复加钱。

### M2 并发与缓存（第 3、6 章）

- [ ] 并发 100 请求充值，最终余额 = 总和
- [ ] 余额缓存，写后失效
- [ ] 缓存击穿保护
- [ ] `go test -race` 通过

### M3 异步与可观测（第 7、9、11 章）

- [ ] 充值成功发消息（Kafka 或内存实现）
- [ ] 消费端幂等
- [ ] 结构化日志 + trace_id
- [ ] `/metrics` 暴露 QPS/延迟/错误
- [ ] Grafana 看板 + 1 条告警规则

### M4 稳定性（第 10、13 章）

- [ ] 单用户限流 10 QPS
- [ ] 下游超时 300ms + 熔断
- [ ] k6 压测报告（QPS、P99、错误率）
- [ ] pprof 找到一次瓶颈并优化

### M5 交付（第 12、14~17 章）

- [ ] 单元/集成/E2E 三层测试
- [ ] CI 流水线全绿
- [ ] Docker 多阶段构建
- [ ] K8s 部署 + 探针 + 资源限制
- [ ] 接口文档（OpenAPI）
- [ ] 安全检查清单全过
- [ ] 写一份上线与回滚方案

## 评分标准

| 维度 | 权重 |
|---|---|
| 正确性（幂等/并发/事务） | 30% |
| 测试覆盖 | 20% |
| 可观测性 | 15% |
| 稳定性（限流/熔断/压测） | 15% |
| 交付（CI/Docker/K8s/文档） | 20% |

## 提交物

1. 代码仓库（含 README、迁移、测试）；
2. 压测报告；
3. 架构图 + 时序图；
4. 上线/回滚方案；
5. 故障复盘（自己制造一次故障并恢复）。
